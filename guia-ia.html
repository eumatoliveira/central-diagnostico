Guia de IA local

Use um ambiente de teste, uma conta comum e dados públicos ou sintéticos no primeiro laboratório.

1. Iniciar o Ollama em modo local

Instale o Ollama pelo canal oficial. Feche uma instância já aberta antes de iniciar outra na mesma porta.

Windows PowerShell

$env:OLLAMA_HOST = '127.0.0.1:11434'
$env:OLLAMA_NO_CLOUD = '1'
ollama serve

Linux

OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 ollama serve

OLLAMA_HOST limita a API à interface local. OLLAMA_NO_CLOUD desabilita os recursos de nuvem do Ollama. Se a instalação roda como serviço, aplique as variáveis ao serviço e confirme o endereço depois de reiniciar. Em máquinas compartilhadas, isole o serviço e suas credenciais por usuário.

ollama pull gemma4:e2b
ollama list
ollama run gemma4:e2b

pull baixa o modelo e exige rede e espaço no disco. list mostra os modelos locais. run abre a conversa no terminal. Teste com um exemplo sintético antes de usar documentos reais.

2. Verificar o serviço e os recursos

Windows PowerShell

Get-NetTCPConnection -LocalPort 11434 -State Listen
Invoke-RestMethod http://127.0.0.1:11434/api/tags
nvidia-smi

Linux

ss -ltn 'sport = :11434'
curl --fail --silent --show-error http://127.0.0.1:11434/api/tags
nvidia-smi

A primeira linha confere onde a API escuta. Uma instância local deve aparecer em 127.0.0.1. Uma escuta em 0.0.0.0 permite conexões por outras interfaces conforme a política de rede. A segunda linha consulta a lista de modelos. nvidia-smi mostra a GPU, o driver e o uso de memória quando disponível.

3. Preparar, baixar e rotular dados

Registre de onde veio cada conjunto, qual licença permite seu uso, a revisão, a data e o responsável. Remova segredos e dados pessoais antes de rotular. Separe treino, validação e teste antes de criar versões aumentadas do mesmo exemplo.

python -m venv .venv
.venv\Scripts\python.exe -m pip --version
python3 -m venv .venv
.venv/bin/python -m pip --version

venv isola dependências do projeto. Use a primeira sequência no Windows e a segunda no Linux. Instale a CLI hf e a ferramenta de rotulação nesse ambiente seguindo suas instruções oficiais e fixando versões aprovadas.

hf download ORGANIZACAO/CONJUNTO --repo-type dataset --revision COMMIT --include '*.parquet' --local-dir data/raw

Substitua organização, conjunto e commit pelos do material aprovado. --repo-type seleciona o catálogo de dados. --revision fixa a versão. --include limita o formato e --local-dir escolhe a pasta. Inspecione o esquema, tamanho e amostras antes de importar.

No Label Studio, crie um projeto privado, escreva critérios de cada rótulo e pilote com uma amostra. Revise divergências entre anotadores, exporte os rótulos e versione o arquivo. Use uma categoria para casos ambíguos que precisam de revisão.

4. Treinar um adaptador e avaliar

  1. Escolha um checkpoint com licença para fine-tuning, fixe a revisão e verifique a origem dos pesos. Prefira arquivos Safetensors de fonte aprovada. Mantenha código remoto desabilitado.
  2. Meça o modelo base com um conjunto de teste congelado. Para classificação, acompanhe precisão e recall por classe. Para respostas, defina critérios e faça revisão humana por amostra.
  3. Monte os pares de entrada e saída esperada. Comece com um treino supervisionado pequeno usando TRL e um adaptador LoRA. Registre seed, revisão de dados, versões das bibliotecas e configuração de treino.
  4. Compare o adaptador com o modelo base no mesmo teste. Verifique vazamento entre conjuntos, regressão e exposição de dados. Promova apenas um artefato aprovado e mantenha o checkpoint base para reverter.
nvidia-smi --query-gpu=name,memory.used,memory.total,temperature.gpu --format=csv

Durante o treino, a consulta acima mostra uso de memória e temperatura por GPU. Reduza batch ou comprimento de sequência se faltar memória. Em cluster, associe métricas ao nó e ao job antes de alterar os limites. O fine-tuning usa uma ferramenta de treino como TRL. O Ollama serve a etapa de inferência.
